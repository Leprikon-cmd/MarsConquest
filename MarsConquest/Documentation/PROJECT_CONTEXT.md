## Назначение

Mars LogBook — локальный iPhone-журнал партий в «Покорение Марса». Он помогает собрать команду,
зафиксировать результаты экспедиции, сохранить детали и наблюдать личную статистику владельца.

Подробная продуктовая граница: [PRODUCT_CONCEPT.md](PRODUCT_CONCEPT.md).
Тон и правила интерфейса: [APP_PERSONALITY.md](APP_PERSONALITY.md).

## Ключевые решения

| Решение | Правило |
|---|---|
| Устройство | Новая работа ориентирована только на iPhone. |
| Хранилище | Core Data, активная модель `GameDataModel 12`; старые модели не переписываются. |
| Идентичность | `SavedPlayer.id` — стабильный UUID человека; имя не используется для автоматической привязки. |
| Сохранение | Новые партии, резервное восстановление и исторический импорт пишутся в отдельном контексте Core Data. |
| Архив | Повторный UUID не создаёт копию и не перезаписывает текущую запись. |
| Настройки | Язык, звук и тестовый режим остаются на конкретном iPhone; коллекция принадлежит профилю. |
| Режим ведущего | Это дополнительный локальный режим: один iPhone остаётся у ведущего, а игроки продолжают играть физическими компонентами. |
| Локализация | Новые записи сохраняют постоянные игровые ключи, а текст выбирается по активному языку. |
| Интерфейс | Нижняя навигация учитывается единым `JournalNavigationLayout.contentBottomClearance`. |
| Комментарии | Каждый Swift-файл имеет русскую шапку: «Зачем», «Кто», «Что можно менять руками». |

## Очередь работы

### P5 — пульт ведущего, ждёт проверки на iPhone

**Принцип.** Телефон — инструмент ведущего, а не предмет, который передают между игроками.
Приложение показывает состояние партии и переключает его только по действиям ведущего; карты,
ресурсы и решения остаются на столе.

**Включение.** В настройках новой экспедиции есть необязательный «Режим ведущего».
Без него сохраняется нынешний маршрут прямо к журналу результатов. С ним после состава команды
открывается экран порядка хода: ведущий расставляет участников и выбирает игру с таймером либо без.
Поколение начинается с первого и ведётся приложением; в журнал результатов оно подставляется
автоматически, без отдельного пикера.

**Формат записи.** Обычная партия остаётся «Классикой». Партия с ограничениями получает отдельный
формат «Спортивный режим». У неё хранится неизменяемый снимок спортивного регламента: версия,
лимит времени на участника, лимит поколений и правило случая, когда время превысили все. Настройки
запираются при старте партии: позднее они не меняют уже внесённую запись. Регламент не подменяет
очки, места, состав и остальные факты игры.

**Игра без таймера.** На экране видны поколение и метка первого игрока. Ведущий нажимает
«Завершить поколение», а приложение увеличивает номер поколения и передвигает метку к следующему
участнику в заданном порядке.

**Игра с таймером.** Это шахматный контроль с единым настраиваемым лимитом на каждого участника
(например, 30 минут или 2 часа). У каждого игрока свой обратный отсчёт. После нуля счётчик
продолжает показывать красное превышение — так сохраняется точный размер просрочки. Ведущий
нажимает «Завершить ход» — время текущего игрока останавливается, у следующего непасовавшего
запускается. «Пас» отмечает игрока как завершившего поколение и передаёт время дальше. Когда
спасовали все, приложение останавливает таймер и открывает межпоколенческий перерыв для
производства, добора карт и других действий за столом.

После физического добора приложение не может узнать о готовности само. Поэтому ведущий подтвердит
её одной кнопкой «Начать следующее поколение»: номер поколения увеличится, метка перейдёт к
следующему первому игроку и его таймер начнёт отсчёт сразу.

**Завершение экспедиции.** Ведущий может перейти к журналу результатов из текущего состояния.
Приложение передаёт в него уже показанный номер поколения и не увеличивает его дополнительно.

**Превышение времени.** Когда личный лимит исчерпан, игрок остаётся в партии, а приложение
фиксирует отметку «лимит времени превышен» и размер просрочки. Очки, тай-брейк и классические
места в журнале остаются без изменений. Пока хотя бы один участник уложился во время, победитель
по спортивному регламенту выбирается из них по классическому результату.

Если время превысили все, ведущий заранее выбирает одно из трёх правил:

1. победа с наименьшим превышением;
2. победа по классическим очкам и обычному тай-брейку;
3. проиграли все.

Выбранное правило и итог по регламенту хранятся рядом с партией, а не подменяют её фактические
результаты.

**Лимит поколений.** В спортивном режиме ведущий может задать верхнюю границу, например 14-е
поколение. Если к этому моменту Марс не терраформирован, все участники проигрывают по регламенту.
Запись всё равно сохраняется как обычная партия с её очками и местами, но получает итог
«лимит поколений достигнут». Поскольку приложение не видит физическое поле, ведущий явно
подтверждает: «Марс терраформирован» или «Лимит достигнут».

**Журнал и аналитика.** В архиве игр есть фильтр «Все / Классика / Спортивный режим».
Статистика использует тот же фильтр, поэтому результаты режимов можно смотреть вместе либо не
смешивать. Для спортивного режима отдельно считаются победы по регламенту, превышения времени,
остаток или расход времени и партии, завершившиеся лимитом поколений. В дальнейшем в статистике
и сети сопоставляются только партии с одинаковой версией регламента; произвольные настройки
остаются честно помеченными как отдельный вариант, а не смешиваются с быстрым форматом.

**Подготовка к сети.** Спортивная партия хранит переносимые данные регламента и исхода:
стабильный идентификатор и версию правил, параметры лимитов, время каждого участника, итог
регламента и классический результат. Синхронизация, подтверждение участников и защита от
недостоверных записей остаются задачами P6–P7.

**Собрано.** Настройка порядка, режим без таймера, шахматный контроль, пас, пауза,
межпоколенческий перерыв, отмена последней команды, лимит поколений, три правила общего
превышения, восстановление незавершённой экспедиции, фильтры статистики и помощник драфта.
До закрытия P5 нужно пройти ручный сценарий из [TESTING.md](TESTING.md).
