# Mars LogBook — карта проверок

Последнее обновление: 2026-09-09

Текущий автоматический контур предназначен только для iPhone. Проверки iPad начнутся после
отдельного решения владельца проекта.

## Что есть сейчас

### Модульные тесты — 25 проверок

- `ScoringRulesTests` — 8 быстрых проверок подсчёта: категории очков, политика с Turmoil,
  достижения, первое и второе места наград, ничьи и плотная нумерация рейтинга.
- `PlayerValidationTests` — 4 проверки состава: нормализация имени, редактирование самого себя,
  уникальность корпорации и занятые прологи.
- `JournalCompatibilityTests` — 3 проверки старой истории: написание `Элада`, приоритет
  постоянного идентификатора поля и сохранение неизвестного поля как неизвестного.
- `MarsConquestTests` содержит 6 проверок надёжности журнала: обратные связи активной модели,
  полная запись партии, изоляция сохранения, безопасный отказ с повторной попыткой и миграция
  SQLite 5 → 11, в том числе подробная проверка связей для 10 → 11.
- Там же пока находятся 4 отложенные проверки карьеры: привязка истории к владельцу,
  начисления и вехи, условия уровня и титул за пять экспедиций одной корпорацией.

Большинство проверок Core Data используют временное хранилище в памяти. Тест миграции создаёт
отдельную временную SQLite-базу, записывает её моделью 10 и открывает моделью 11.

### UI-тесты — 5 проверок

- `testJournalNavigationFitsInsideApplicationWindow` — нижняя навигация существует и помещается
  в окне iPhone.
- `testNewExpeditionKeepsStartGameButtonReachable` — маршрут «Журнал → Новая экспедиция →
  Высадка → редактор владельца → команда» и доступность основных кнопок.
- `testExpeditionCanBeRecordedAndOpenedFromJournal` — маршрут «владелец → команда → журнал
  экспедиции → подтверждение → подробности»: выбирает поколение, вносит запись и проверяет его
  отображение в деталях сохранённой партии.
- `testLaunchPerformance` — измеряет время запуска; фиксированного порога пока нет, поэтому это
  диагностический замер, а не гарантия производительности.
- `MarsConquestUITestsLaunchTests.testLaunch` — сохраняет снимок после запуска; сам по себе
  не подтверждает правильность содержимого экрана.

Каждый UI-тест запускает приложение с отдельной чистой базой в памяти и тестовым владельцем.
Обычная база приложения и история симулятора в этих проверках не используются.

## Какие наборы запускать

### Правила

Запускать после изменений `ScoreManager`, очков, наград, достижений или тай-брейка:

- `ScoringRulesTests`.

### Состав экспедиции

Запускать после изменений добавления и редактирования игрока:

- `PlayerValidationTests`;
- целевой UI-тест новой экспедиции, если изменялся экран.

### Надёжность журнала

Запускать после изменений `GameSaver`, Core Data или состава сохраняемой партии:

- `currentModelHasReciprocalJournalRelationships`;
- `gameSaverPersistsCompleteJournalEntry`;
- `gameSaverKeepsUnrelatedContextChangesIsolated`.
- `failedSaveLeavesNoEntryAndRetryDoesNotDuplicateIt`.

### Миграция

Запускать обязательно после каждой новой версии модели Core Data:

- `modelsFiveThroughNineMigrateToCurrentJournalModel` — проверяет чтение минимальных записей из
  моделей 5–9 после перехода к текущей модели.
- `modelTenStoreMigratesToCurrentModelWithRelationshipsIntact` — подробно проверяет переход
  10 → 11 вместе с игровыми связями.
- При следующей версии модели добавить переход от предыдущей актуальной версии к новой.

### Совместимость старых записей

Запускать после изменений постоянных идентификаторов, импорта и распознавания исторических данных:

- `JournalCompatibilityTests`;
- проверки сохранения и миграции, если менялась Core Data.

### UI smoke на iPhone

Запускать после изменений главного экрана, нижней навигации, новой экспедиции и состава:

- `testJournalNavigationFitsInsideApplicationWindow`;
- `testNewExpeditionKeepsStartGameButtonReachable`.
- `testExpeditionCanBeRecordedAndOpenedFromJournal`.

### Перед сборкой TestFlight

1. Запустить все модульные тесты.
2. Запустить функциональный UI smoke-набор.
3. Отдельно запустить замер запуска и снимок, если они нужны для сравнения.
4. На физическом iPhone проверить обновление со старой базой, создание новой партии,
   повторный запуск и открытие сохранённых подробностей.
5. Повторить основной ручной сценарий на русском и английском языках.

### Ручная проверка резервного архива

1. В настройках откройте «Архив журнала» и создайте резервную копию в «Файлах».
2. Сразу выберите этот же файл через «Восстановить архив журнала» и подтвердите внесение.
3. Убедитесь, что приложение сообщает: сведения уже отражены в журнале; число партий не меняется.
4. Для полного этапа P4 на отдельном чистом iPhone или после осознанной очистки данных приложения
   восстановите файл и сверьте число партий, профиль владельца, результаты, достижения, награды,
   колонии, аватар и селфи. Повторно примите тот же файл: дубликаты не должны появиться.

## Запуск в Xcode

Для проверок используется схема `MarsConquest`. Сохранённая схема `MarsConquest 1` сейчас не
содержит тестовых целей и для проверок не используется.

В Test Navigator можно нажать ромб рядом с конкретным тестом или названием набора, например
`ScoringRulesTests`. `Product → Test` запускает весь контур, включая более медленные UI-тесты.

При работе над узкой задачей сначала запускается соответствующий целевой набор. Полный прогон нужен
перед выпуском, после изменения общей инфраструктуры или когда затронуто несколько подсистем.

## Чего тесты пока не доказывают

- Нет автоматической проверки повторного запуска приложения с уже сохранённой партией.
- Нет цикла экспорта и восстановления — сама функция резервной копии ещё не реализована.
- Исторические миграции 5–10 проверяются на минимальных временных SQLite-базах; реальные
  пользовательские базы и полный состав данных каждой версии ещё не покрыты.
- Не задан допустимый порог времени запуска.
- Автоматических проверок iPad нет и сейчас не требуется.
